# vroid-studio-mcp

[한국어](README.ko.md) | [English](README.md) | [Русский](README.ru.md)

![vroid-studio-mcp 작업 과정](docs/media/promo.gif)

`vroid-studio-mcp`는 **MCP 인터페이스를 제공하는 VRoid Studio 2.14.0 확장 도구**입니다.
앱 내부의 BepInEx 플러그인을 통해 AI 에이전트가 VRoid의 내부 API를 호출하여 캐릭터를 만들고
편집합니다. 실험적 기능으로 ComfyUI를 이용한 텍스처 작업과 Blender를 이용한 얼굴 형상·액세서리
작업도 연결합니다.

MCP는 편집 명령을 주고받는 인터페이스입니다. 플러그인은 추가 형상을 VRoid Studio 안에서 표시하고,
저장한 모델을 다시 열 때 복원하는 역할도 합니다.

## 작업 예시: 교복 아스나

**블루 아카이브 아스나의 교복 모습**을 재현하는 팬 작업입니다. Mx2J의 공식 스탠딩 원화를 주된
레퍼런스로 삼아 VRoid 기본 얼굴 파라미터·머리카락·의상을 조정하고, 편집한 텍스처와 눈 주변 형상,
액세서리, 헤일로를 결합했습니다. 현재도 다듬고 있는 작업입니다.

![VRoid Studio에서 본 아스나 V49의 비스듬한 모습](docs/images/asuna/asuna-v49-three-quarter.png)

| 전신 | 얼굴과 눈 디테일 |
|---|---|
| [![아스나 V49 전신 정면](docs/images/asuna/asuna-v49-body.png)](docs/images/asuna/asuna-v49-body.png) | [![아스나 V49 얼굴 확대](docs/images/asuna/asuna-v49-face.png)](docs/images/asuna/asuna-v49-face.png) |

이미지는 **V49 모델을 저장한 뒤 다시 열어 촬영한 앱 미리보기 원본**입니다. 생성형 AI로 그린 완성 예상도나
Blender 렌더가 아닙니다. V49에서는 실행 상태·기존 데이터 보존·저장 후 재열기에 관한 56개 검사를
통과했고, Blender 셰이프 키 배열 153개와 내장 PNG도 확인했습니다. 이 검사는 기술적 동작을 확인한
것이며, 원화와의 유사도나 완성도를 보증하지는 않습니다. 머리카락·리본·의상은 계속 수정 중이고,
이후 제작한 V50 머리 리본 후보는 위 이미지에 포함하지 않았습니다.
[스크린샷 출처와 검증 범위](docs/images/asuna/README.md).

이 결과는 레퍼런스 비교와 부분 수정을 반복해서 만든 사례입니다. 이미지 한 장에서 자동으로 완성된
캐릭터를 생성하는 기능을 뜻하지 않습니다. 캐릭터 모델 파일과 외부 원본 에셋은 저장소에 포함하지 않습니다.

## 무엇이 저장되고, 언제 플러그인이 필요한가요?

| 구분 | 역할 | 다시 열 때 |
|---|---|---|
| VRoid 기본 편집 | 프리셋, 파라미터, 색상, 기본 머리카락, 편집 가능한 텍스처 | 일반 모델 데이터로 저장되며, 추가 형상 표시 기능과 별개로 유지됩니다. |
| 실험적 형상 확장 | 동일한 원본 메시를 바탕으로 한 얼굴 수정과 아이라인·속머리층·옷깃·리본·헤일로 등 | 패키지와 텍스처가 `.vroid` 안에 저장됩니다. 표시하려면 이 플러그인이 로드되어야 합니다. |
| 외부 제작 도구 | ComfyUI 텍스처 워크플로, Blender 메시 제작·베이킹 | 해당 제작 단계에서 사용합니다. 저장된 내장 결과를 다시 열기만 할 때는 필요하지 않습니다. |

### 확장 모델을 여는 순서

1. **BepInEx와 `VroidStudioMcp.dll`이 설치된 VRoid Studio**를 실행합니다. 작업용 복사본을 따로
   두었다면 그 폴더의 `VRoidStudio.exe`를 직접 실행하세요. `.vroid`를 더블클릭하면 파일 연결 설정에
   따라 플러그인이 없는 다른 설치본이 실행될 수 있습니다.
2. 앱 안에서 저장한 `.vroid`를 열고 모델 로딩이 끝날 때까지 기다립니다. 플러그인이 내장 형상을
   자동으로 복원합니다. 이미 저장된 내장 결과를 여는 데 JSON을 따로 가져오거나 Blender·ComfyUI를
   켤 필요는 없습니다.
3. 추가 파츠가 보이지 않으면 플러그인이 로드되었는지 확인하고 MCP의 `face_bridge_status`를
   조회합니다. 정상적으로 활성화된 패키지는 저장된 해시와 활성 해시가 같고 실행 오류가 없어야 합니다.
   원본 메시가 바뀌었거나 패키지를 담은 데이터가 사라졌다면
   [복구 절차](docs/face-bridge.md#compatibility-and-recovery)를 따릅니다.

**플러그인이 없는 일반 VRoid Studio에서는 추가 형상이 활성화되지 않습니다.** `.vroid`에 저장했다고
해서 추가 파츠가 VRoid의 기본 편집 아이템으로 바뀌는 것은 아닙니다. 임의의 Blender 장면 가져오기,
추가 형상을 포함한 기본 VRM 내보내기, 천 시뮬레이션, 모든 표정·애니메이션 조합은 검증 범위 밖입니다.
기본 편집을 더 진행하기 전에 확장 모델과 체크포인트를 따로 보관하세요.

## 주요 기능

- **실험적 눈화장 편집** — 알파 채널을 명시적으로 교체하여 아이라인의 불투명도와 외곽 형태를
  바꾸고, RGBA 원본을 정확히 백업·복원합니다. 기본 아이라인·속눈썹·FacePaint 아이섀도의 편집,
  화면 변화, 저장 후 재열기를 검증했습니다. FacePaint를 편집 가능한 레이어로 준비할 때는 모델
  체크포인트를 먼저 만듭니다. [범위와 예시](docs/makeup-editing.md).
- **실험적 머리카락 형상 편집** — 그룹과 가닥을 조회하고 브러시 가닥의 루트 이외 제어점을
  이동·복원합니다. 백업, 리비전 검사, 렌더 확인을 포함합니다. 앞머리 테스트 모델의 저장·재열기를
  검증했으며, 이미지에서 자동으로 헤어스타일을 재구성하거나 가이드를 편집하는 기능은 아직 없습니다.
  [API와 렌더 요구 사항](docs/external-api.md#hair-geometry).
- **캐릭터 생성·편집·저장** — 새 캐릭터를 만들거나 기존 모델을 열고 편집한 뒤 `.vroid`로 저장합니다.
- **에디터 제어** — 지원되는 `Face`, `Hairstyle`, `Body`, `Outfit` 섹션의 카테고리, 프리셋,
  개별 슬라이더와 색상을 다룹니다.
- **실시간 시각 피드백** — 모델 렌더와 프리셋 썸네일을 에이전트에 제공하여 결과를 보고 판단하게 합니다.
- **고품질 미리보기** — MSAA, 슈퍼샘플링(SSAA), 이방성 필터링을 설정할 수 있습니다.
- **읽기 쉬운 프리셋 이름** — 기본 내부 ID 대신 의미를 구별할 수 있는 이름을 제공합니다.
- **영어 UI 명칭 보정** — 서로 다른 슬라이더에 같은 이름을 붙인 기본 영어 번역을 보정합니다.

## 동작 방식

- 플러그인이 **VRoid Studio 내부 API**를 직접 호출합니다. 마우스·키보드를 흉내 내는 대신 엔진의
  메서드를 사용하고, 렌더된 미리보기에서 시각 피드백을 얻습니다.
- Blender에서 만든 추가 형상은 플러그인의 별도 렌더러가 표시합니다. 대응하는 패키지는 앱의
  직렬화 기능을 통해 저장하고, 모델을 열거나 지원되는 재구성이 끝나면 복원합니다.
  [얼굴·액세서리 브리지](docs/face-bridge.md)를 참고하세요.
- GUI를 조작하지 않으므로 **앱이 백그라운드에 있거나 최소화되어 있어도 작업을 계속합니다.**
- **Wine을 지원합니다.** Linux에서 Wine으로 VRoid Studio를 실행하면 경로를 양방향으로 변환하므로,
  에이전트와 스크립트는 일반 Linux 경로로 파일을 열고 저장할 수 있습니다.

## 요구 사항

- **VRoid Studio 2.14.0** — Windows 또는 Wine 환경.
  [공식 사이트](https://vroid.com/en/studio).
- **Unity IL2CPP용 BepInEx 6** —
  [BepInEx-Unity.IL2CPP-win-x64-6.0.0-be.788 다운로드](https://builds.bepinex.dev/projects/bepinex_be/788/BepInEx-Unity.IL2CPP-win-x64-6.0.0-be.788%2B5b766a3.zip).
  플러그인이 사용하는 나머지 실행 구성 요소는 BepInEx에 포함되어 있습니다.
- **선택적 제작 도구** — 외부 텍스처 작업용 ComfyUI, 실험적 형상 브리지용 Blender와 Python.
  각각 별도로 설치합니다. 기본 에디터 제어나 이미 저장된 확장 모델을 다시 여는 데는 필요하지 않습니다.

## 설치

1. **요구 사항**에 있는 BepInEx를 VRoid Studio 폴더에 설치하고 앱을 한 번 실행하여 초기 설정을
   완료합니다.
2. 플러그인 파일을 다음 위치에 복사합니다.

   ```text
   <VRoidStudio>/BepInEx/plugins/VroidStudioMcp.dll
   ```

3. 두 데이터 폴더를 `VRoidStudio.exe`가 있는 폴더에 복사합니다.

   ```text
   <VRoidStudio>/i18n/      # 영어 UI 명칭 보정 데이터
   <VRoidStudio>/labels/    # 프리셋 이름 데이터
   ```

4. 로그 파일을 남기지 않으려면 제공된 BepInEx 설정도 복사합니다. 선택 사항입니다.

   ```text
   <VRoidStudio>/BepInEx/config/BepInEx.cfg
   ```

5. VRoid Studio를 실행합니다. MCP 엔드포인트는 `http://127.0.0.1:17891/mcp`입니다.

### 릴리스 구성

압축 파일에는 **플러그인과 관련 데이터만** 제공합니다. VRoid Studio와 BepInEx는 포함하지 않으며
각각 따로 설치해야 합니다.

```text
BepInEx/plugins/VroidStudioMcp.dll   플러그인
BepInEx/config/BepInEx.cfg          로그 출력을 끈 BepInEx 설정
i18n/                              영어 UI 명칭 보정 데이터
labels/                            프리셋 이름 데이터
README.md  README.ko.md  README.ru.md  LICENSE
```

### 설치 프로그램이 필요한가요?

현재 배포 방식은 **플러그인·데이터 ZIP**이며, 별도의 설치 프로그램은 제공하지 않습니다.
배포자는 [빌드 준비](AGENTS.md#build-and-run)를 마친 뒤
[패키징 스크립트](tools/package-release.sh)로 ZIP을 만들 수 있습니다. 추후 설치 프로그램을
추가하면 올바른 앱 폴더 선택과 실행 바로가기 생성을 도울 수 있습니다. 설치 프로그램이 있어도
확장 모델을 표시하려면 플러그인이 로드되어야 하며, VRoid Studio와 BepInEx는 별도로 준비해야 합니다.

## 시작하기

MCP 클라이언트에 로컬 엔드포인트를 등록합니다. 예를 들면 다음과 같습니다.

```json
{ "mcpServers": { "vroid-studio-mcp": { "url": "http://127.0.0.1:17891/mcp", "type": "http" } } }
```

그다음 에이전트에게 원하는 작업을 요청합니다. 예: *"단발머리에 초록색 눈을 가진 여성 캐릭터를
만들어서 문서 폴더에 저장해 줘."* 에이전트가 현재 섹션·프리셋·파라미터를 조회하고, 변경 사항을
적용한 뒤 렌더된 미리보기에서 결과를 확인합니다.

## 설정

설정 파일은 `<VRoidStudio>/BepInEx/config/com.kokokoshka.vroidstudiomcp.servers.json`입니다.
주요 항목은 다음과 같습니다.

| 항목 | 기본값 | 설명 |
|---|---|---|
| `enabled` | `true` | 제어 서버 활성화 여부 |
| `msaa_samples` | `4` | 미리보기 계단 현상 완화. 앱을 재시작해야 적용됩니다. |
| `render_scale` | `2` | 미리보기 렌더 해상도 배율 |
| `aniso_filtering` | `true` | 비스듬한 표면의 텍스처 선명도 개선 |

미리보기가 느리면 `render_scale`을 `1`로 낮추세요.

서버 주소와 관련 설정은 앱 안에서도 바꿀 수 있습니다. 계정 아이콘에서 **설정(Settings)**을 열고,
상단의 **Programmatic Control (MCP)** 항목을 확인하세요.

## 실험적 텍스처 편집과 ComfyUI

MCP로 편집 가능한 레이어 조회, PNG 내보내기·가져오기, 백업 복원을 할 수 있습니다. 최초 검증 대상은
홍채 레이어이며, 실제 ComfyUI/Qwen 편집, 3D 미리보기 변화, 정확한 원본 복원, `.vroid` 저장·재열기를
확인했습니다. 별도 Python 브리지는 설정 가능한 API 워크플로, 적용 전 미리보기, 알파 검증,
결과가 일정한 모의 실행 모드를 제공합니다.
[설정과 명령](tools/comfy-bridge/README.md), [검증 결과와 제약](docs/texture-interop-findings.md)을
참고하세요. 커스텀 아이템은 현재 읽기 전용 조회만 지원하며, 가져오기·적용과 VRM 내보내기는
구현하지 않았습니다.

### 권장 이미지 제작 방식

**캐릭터의 그림 디테일에는 덕테이프(Duct Tape) 같은 고품질 이미지 생성·편집 모델을 적극적으로
활용하는 것을 권장합니다.** 모델 선택은 텍스처 품질에 큰 영향을 줄 수 있습니다. 원본 레퍼런스를
기준으로 홍채 그림, 눈썹, 아이라인·눈화장 마스크, 머리카락의 그림 디테일, 의상 문양 등을 제작하세요.
포함된 Qwen 워크플로는 연결 과정을 보여주는 예제이며, 최상의 화질을 보장하는 설정은 아닙니다.

1. 현재 텍스처를 내보내고 수정할 파츠, UV 위치와 알파 마스크를 먼저 확인합니다.
2. 고품질 이미지 모델로 해당 파츠를 생성·편집하고 후보를 원본과 비교합니다. 생성 결과를 검토할 때도
   디자인 판단의 기준은 원본 레퍼런스로 유지합니다.
3. 검토한 그림을 실제 아틀라스에 맞춥니다. ComfyUI로 합성·색상 조정·알파 처리를 한 뒤 텍스처 도구로
   가져오고 모델 위에서 확인합니다.
4. 정면·비스듬한 시점과 저장 후 재열기를 확인합니다. 눈의 실제 개구부, 머리카락 볼륨, 부착 위치와
   관통 문제는 VRoid 형상 제어나 Blender 작업으로 별도로 맞춥니다.

덕테이프는 외부 제작 도구의 예시이며, 저장소에 모델이나 전용 서비스 연동이 내장되어 있다는 뜻은
아닙니다. 사용 가능한 이미지 도구나 설정한 ComfyUI 워크플로를 이용하고, 접근 권한과 모델 환경은
별도로 준비합니다. 생성한 그림이 자동으로 맞춤형 3D 파츠가 되는 것은 아닙니다.

## macOS

macOS 지원은 **연구 단계**이며 현재 릴리스에 포함되지 않습니다. Apple Silicon에서도 구현은
가능하지만, BepInEx 업스트림에 아직 포함되지 않은 BepInEx·Il2CppInterop 빌드가 필요합니다.
[macOS 문서](docs/macos.md)를 참고하세요.

## 실험적 Blender 얼굴 브리지

동일한 원본 메시에서 만든 Blender 얼굴·눈 작업을 `face_import`로 앱에 가져오고, `.vroid` 안에 저장한 뒤
다시 열 때 복원할 수 있습니다. 지원되는 뼈에 연결한 액세서리도 같은 확장 기능으로 표시합니다.
**추가 형상을 표시하려면 플러그인이 필요합니다.** 내보내기 도구는 대응하는 원본 메시 캡처와
일부 표정 상태를 대상으로 하며, 임의의 `.blend`를 가져오는 범용 도구는 아닙니다.
VRM 내보내기 연동은 검증하지 않았습니다.
[작업 절차와 제약](docs/face-bridge.md), [API](docs/external-api.md#blender-face-bridge)를 참고하세요.

## AI 사용 공개

역공학과 초기 구현의 상당 부분은 **OpenCode에서 실행한 DeepSeek V4.1 Flash** 등 AI 코딩
에이전트로 작성했습니다. AI가 만든 결과는 실제 앱에서 검토하고, 동일한 조건에서 반복 가능한
앱 내부 테스트와 실행 중 검사를 통해 검증한 뒤 반영했습니다.

## 권리 안내

이 프로젝트는 상호 운용성과 자동화를 위한 도구입니다. VRoid Studio, BepInEx 등 외부 구성 요소의
권리는 각 소유자에게 있으며, 저장소에 포함하지 않습니다. 사용에 따른 책임은 사용자에게 있습니다.

아스나 스크린샷은 비공식 팬 작업의 기술적 사례입니다. 블루 아카이브 캐릭터 디자인과 외부 에셋의
권리는 각 권리자에게 있으며, 코드의 MIT 라이선스가 해당 디자인이나 에셋에 대한 권리를 부여하지는
않습니다. 이 프로젝트는 해당 권리자와 제휴하거나 승인을 받은 프로젝트가 아닙니다.
